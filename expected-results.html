Heterogeneous GPU–Dataflow Decoding

Project hardware: 8 NVIDIA H200 SXM GPUs for prefill; Cerebras WSE-3 for decode.

Illustrative baseline
GPU-only prefill and decoding on the 8-H200 system.
Illustrative target
GPU prefill plus WSE-3 decoding. The target configuration adds a WSE-3; this is not an equal-cost or equal-power comparison.
Proposed workload and assumptions
  • Generic 8B dense decoder; 32 layers, 8 KV heads, head dimension 128; BF16 weights and KV. This is a proposed workload, not a claim about the model already tested.
  • 16 concurrent requests; exactly 8,192 input and 1,024 output tokens per request. Identical weights, prompts, precision, and generation settings.
  • A 30-minute steady-state window after a 5-minute warm-up; 5 planned repetitions. No repetitions have been run for this dataset.
  • The assumed KV layout needs 128 KiB per cached token: 18 GiB at 16 × 9,216 tokens. Approximately 16 GB of BF16 weights plus KV and runtime buffers must fit the wafer.
  • GPU–wafer state transfer, layout conversion, and correctness matching are prerequisites; these target figures do not establish that the handoff is implemented or meets timing.
  • The target assumes an independently optimized decode-kernel and routing stack; it is not extrapolated from the current CSL-LLM SDK functional-inference timing.

Long-Horizon Agent KV-Cache Scheduling

Project hardware: 8 NVIDIA H200 GPUs; 50 concurrent agent sessions.

Illustrative baseline
Fixed per-session KV allocation with reactive eviction and no scheduler-level sharing of common prefixes.
Illustrative target
A proposed residency-aware scheduling policy with shared-prefix reuse. These policy choices are evaluation assumptions, not assertions about completed implementation.
Proposed workload and assumptions
  • The same generic 8B, 32-layer BF16 GQA model as the decoding scenario; 8 KV heads of dimension 128.
  • 50 sessions: 20 at 16,384 tokens, 20 at 32,768, and 10 at 65,536; mean context length 32,768 tokens.
  • TP=1 model workers spread across 8 GPUs; load-balanced session assignment. A shared 8,192-token prefix and 1–30 s tool pauses are proposed trace characteristics.
  • One-hour fixed replay trace after a 15-minute warm-up; 5 planned repetitions. Identical request arrival times and token sequences.
  • The unshared live-token KV footprint is 200 GiB across the system. Allocated pool figures include spare capacity and fragmentation; they are not total GPU memory.

Distributed RL Rollout Scheduling

Project hardware: 256 NVIDIA A100 80GB GPU worker slots at NERSC, as specified for the project; node topology is not assumed.

Illustrative baseline
Static task assignment and default vLLM serving without speculative decoding.
Illustrative target
Go scheduling layer with dynamic work assignment, configured vLLM batching, and verified speculative decoding.
Proposed workload and assumptions
  • Generic 8B BF16 target model; a 0.5B draft model is an illustrative speculative-decoding choice. TP=1; matched output correctness rules.
  • Input lengths of 1K/4K/8K tokens in a 25%/50%/25% mix; generated lengths span 512–4,096 tokens.
  • Five proposed 2-hour trace replays at each scale, plus a separate 24-hour reliability run with 100,000 scheduled tasks.
  • Idle time means GPU-worker wall time without an active rollout batch; it is not SM utilization.
  • A same-feature scheduler-only ablation and a same-scheduler speculative-decoding ablation are required to attribute gains.

Fused FPGA Instruction on U280

Project hardware: Xilinx U280; HLS with dedicated buffers around fixed systolic-array IP; ARM C++ compiler interface.

Illustrative baseline
Separate GEMM, bias-add and ReLU operations with intermediate off-chip writes.
Illustrative target
The same compute IP with buffered fusion exposed as one custom instruction.
Proposed workload and assumptions
  • Illustrative workload: 1,024 × 1,024 INT16 GEMM followed by bias and ReLU; INT32 accumulation, INT16 output.
  • Assumed 32 × 32 MAC array at 250 MHz. Its theoretical ceiling is 512 GOP/s when a MAC counts as two operations.
  • 1,000 invocations after 100 warm-ups; 5 planned repetitions. Buffer placement and tile sizes are fixed across the comparison except where fusion requires changes.
  • Device latency excludes host launch and PCIe transfer; host-command overhead is reported separately.
  • Memory traffic includes repeated tile reads as well as intermediate tensors. FPGA resource counts below are illustrative kernel-region counts, not implementation-tool reports.

Streaming Radon Transform on Zynq-7010

Project hardware: Xilinx Zynq-7010; spatial PE pipeline built with HLS and HDL.

Illustrative baseline
Scalar software Radon reference on one ARM Cortex-A9 core; proposed 667 MHz CPU clock.
Illustrative target
An illustrative 8-PE spatial pipeline at 100 MHz, with fixed-point arithmetic and streaming I/O.
Proposed workload and assumptions
  • 256 × 256 grayscale images, 180 projection angles, 512 detector bins; identical geometry, interpolation and boundary conventions.
  • Proposed 16-bit input/fixed-point data path with 32-bit accumulation, compared with an FP32 reference. Precision differs and is governed by an explicit error threshold.
  • 100 fixed test images; 10 warm-ups and 5 planned repetitions. End-to-end FPGA latency includes DMA and output collection.
  • The target frame time includes all angles. It must not be interpreted as one full image or one full transform per clock cycle.
  • The CPU baseline uses no FPGA PL resources; zero in those rows means not instantiated. The target LUT/DSP/BRAM counts are planned budgets, not synthesis measurements.
